# Project Instructions

本文件适用于整个仓库。用户在当前对话中的明确要求优先于本文件。

## 技术栈

- 使用 React 19、TypeScript、Vite、React Router 和 Ant Design 6。
- 组件使用函数组件和 React Hooks，不新增 class 组件。
- 日期处理沿用 `dayjs`；HTTP 请求沿用项目封装的 Axios 实例。
- 未经用户明确同意，不引入新的依赖、状态管理库、请求缓存库或 UI 组件库。

## 目录与职责

- `src/api/<module>/index.ts` 只负责接口请求函数，接口参数和响应类型放在同目录 `types.ts`。
- `src/components` 只放跨业务、可被多个页面复用的通用组件。
- 每个业务页面使用独立目录；只服务于该业务页面的组件必须统一放在该页面目录下的 `components/` 中，不得直接与页面入口 `index.tsx` 平级。
- 路由、菜单、面包屑和页面懒加载统一维护在 `src/router/index.tsx`。
- 通用工具放在 `src/utils`，不要在多个页面重复实现同一工具函数。
- 优先使用 `@/` 路径别名导入 `src` 下模块。
- 当页面包含独立弹窗、复杂表单或较长业务逻辑时，必须拆分为组件，并统一放在当前页面的 `components/` 目录中，不得继续堆积在页面入口文件或直接放在页面根目录中。

## React 与 TypeScript

- 新增代码必须使用 TypeScript，并为组件 Props、接口参数、接口响应和表单值声明明确类型。
- 避免使用 `any`、无依据的类型断言和 `@ts-ignore`；确实无法确定类型时先说明原因。
- Hooks 只能在组件或自定义 Hook 顶层调用，依赖数组必须完整。
- 异步请求必须正确维护 loading 状态，并使用 `try/finally` 保证状态恢复。
- 组件卸载后仍可能返回的异步请求，需要避免继续更新组件状态。
- 可直接从 props 或现有 state 推导的数据不要重复存入 state。
- `useMemo` 和 `useCallback` 只用于有实际价值的稳定引用或计算，例如表格列、下拉选项和传给子组件的回调，不做无意义包裹。
- 常量、选项列表和状态映射放在组件外部；跨文件共享时放入同模块的 `constants.ts`。
- 保持后端字段原名，例如 `region_id`、`app_id`，不要在 API 层擅自转换字段命名。

## API 与数据请求

- 页面和组件不得直接使用 `axios` 或 `fetch`，统一调用 `src/api` 中的业务接口函数。
- API 函数统一使用 `src/utils/request`，不要重复处理 Token、业务状态码和全局错误提示。
- 新接口必须同时补充请求参数和响应类型；无响应数据时使用 `void`。
- 未提供的接口路径、HTTP 方法、字段结构和枚举值不要自行猜测；缺少关键信息时向用户确认。
- 列表页沿用后端分页参数 `page`、`pageSize`，兼容当前项目的 `pagination.total` 和 `total` 返回结构。
- 创建、编辑、删除或状态变更成功后，使用 `message.success` 提示，并按当前筛选和分页状态刷新数据。
- 请求失败默认交给请求层提示；页面没有特殊处理需求时不要重复弹出错误消息。

## UI 与交互

- 不要使用 HTML `fieldset` 进行页面布局或分组展示，统一使用 Ant Design `Card`。
- 优先使用 Ant Design 现有组件和 `@ant-design/icons`，不要手写已有的通用控件或图标。
- 页面文案、表单提示、确认信息和成功提示默认使用中文，并保持同一业务模块用词一致。
- 表单弹窗默认使用垂直布局，提交前调用 `validateFields`，提交期间使用 `confirmLoading` 防止重复提交。
- 弹窗关闭后不应残留上次表单数据；根据场景使用 `destroyOnHidden`、`preserve={false}` 或显式重置。
- 删除、下架等有风险的操作必须二次确认；删除确认需要明确说明操作不可恢复。
- 数字字段使用 `InputNumber`，枚举字段使用 `Select`，布尔字段使用 `Switch` 或 `Checkbox`。
- 表格必须设置稳定的 `rowKey`；长文本使用省略和 Tooltip；时间按项目惯例将 UTC 转为本地时间展示。
- 页面和弹窗需要兼顾窄屏，优先使用 Ant Design 的 `Row`、`Col`、`Flex` 或响应式 CSS。
- 复杂或可复用样式使用 CSS Modules；仅简单、一次性的布局值允许使用内联样式。
- 没有对应接口或能力时，不实现虚假的成功流程；可以省略或禁用入口，并在交付说明中明确缺失条件。

## 改动边界

- 修改前先阅读目标文件、相邻组件、相关 API 类型和已有实现模式。
- 只修改完成当前需求所必需的文件，不顺带重构无关代码。
- 保留用户已有的未提交改动，不覆盖、不回退、不格式化无关文件。
- 优先复用项目已有模式，只有在确实减少复杂度或重复时才新增抽象。
- 接口或 UI 截图与现有代码冲突时，以用户最新提供的信息为准，并在结果中说明关键取舍。

## Validation Commands

- 修改文件后，不要自动运行 `build`、`lint`、`test`、类型检查、格式化、开发服务器或类似命令。
- 只有用户明确要求时，才可以运行上述命令。

## 完成后的回复

- 简要说明修改结果、主要文件和关键行为，不逐行复述实现过程。
- 未运行验证命令时无需将其描述成错误，只需按需说明“根据项目规则未运行”。
- 存在未完成能力、接口信息缺失或已知风险时必须明确指出。
